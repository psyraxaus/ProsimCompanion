## C. PROSIM LAYER

- **SDK loading** (`Sdk/SdkLocator` → `SdkAssemblyResolver.Register` → `SdkConnection` ctor → `SdkConstructorSelector.Create` by reflection, #158): read in full. ## D. SIM LAYER

- **Thread model**: `SimConnectService.ExecuteAsync` (on a `Task.Run` pool thread courtesy of .NET 10's `BackgroundService`) runs the synchronous pump `RunSession`: `EventWaitHandle.WaitOne(500)` → `ReceiveMessage()`; all `OnRecv*` callbacks, `SimVarService.UpdateFromSim`, facility rows and session signals run on that pump thread. Registrations from other threads lock `_gate` and call into `SimConnect` directly (`EnsureRegistered`, `WriteValueAsync` via `Task.Run`, `RequestAirportFacility`) — SimConnect's managed wrapper tolerates cross-thread sends, and the lock serialises them. Finding 2 covers the pinned pool thread.
- **Reconnect**: outer loop, `COMException` → quiet 5 s retry (one log line), `OnRecvQuit` nulls the handle to end the pump, `TearDownSessionSafely` guards the "wrapper assembly missing" JIT trap (good archaeology comment). `DllNotFoundException`/`FileNotFoundException` → `Disabled` and exit (degrade, not fail). Session detection (`SimSessionService` + pure `SimSessionEvaluator`) is testable and tested.
- **winmm rule — confirmed clean.** The only `winmm.dll` P/Invokes in the solution are in `Speech/Recognition/PushToTalkService.cs:99-117`, behind `WinmmGate`, with `joyGetDevCapsW` reachable only from `ScanJoysticksAsync` (the pilot's Scan) and `joyGetPosEx` only from the dedicated poll thread over *present* ids. **Nothing in Sim/App/Audio/Skalarki touches winmm, dinput, XInput or RawInput**, and no timer path anywhere calls `joyGetPosEx`. `VJoyInterface` uses `NativeLibrary.Load(fullPath)` + delegates (no `DllImport`, no `SetDllDirectory`), loaded lazily on first press/Check; `VJoyInputRelay.Dispose` waits ≤3 s on the press semaphore.
